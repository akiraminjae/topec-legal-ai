# iNames 고객센터 문의 내용

## 제목
topecai.co.kr 네임서버(ns1.uhost.co.kr)의 EDNS0 쿼리 간헐적 응답 실패 문의

## 본문

안녕하세요, topecai.co.kr 도메인을 이용 중인 고객입니다.

topecai.co.kr의 서브도메인(www.legal.topecai.co.kr)을 외부 호스팅 서비스(Netlify)에 연결하는 과정에서, Let's Encrypt SSL 인증서 발급이 계속 실패하고 있습니다. 원인을 직접 조사해보니 **일반적인 DNS 조회로는 재현되지 않지만, EDNS0 옵션(DNSSEC OK 플래그)이 포함된 쿼리에서는 재현되는 특정 네임서버의 결함**을 확인했습니다. 아래 내용 확인 및 조치 부탁드립니다.

### 증상
topecai.co.kr의 네임서버 2대에 동일한 조건으로 각각 10회씩 반복 질의한 결과입니다.

- **ns1.uhost.co.kr (202.31.187.220)**: EDNS0 옵션을 포함한 UDP 쿼리 10회 중 **5회 타임아웃**(정확히 한 번씩 번갈아 응답/무응답하는 패턴). EDNS 옵션 없는 일반 쿼리는 10/10 정상 응답.
- **ns2.uhost.co.kr (219.251.156.14)**: 동일 조건(EDNS0 포함)에서 10/10 모두 정상 응답.

즉, **ns1.uhost.co.kr 서버만** EDNS0가 포함된 쿼리 중 약 50%를 응답 없이 누락시키고 있습니다. 일반 nslookup 등 EDNS를 사용하지 않는 조회 도구로는 문제가 드러나지 않아 정상으로 보일 수 있습니다.

### 영향
Let's Encrypt(SSL 인증서 발급 시스템), Cloudflare(1.1.1.1) 등 대부분의 최신 DNS 검증/리졸버는 EDNS0를 기본적으로 사용하기 때문에, 이 도메인에 대한 조회가 확률적으로(약 50%) 실패합니다. 그 결과:
- 외부 호스팅 서비스에서 SSL 인증서 자동 발급이 계속 실패함
- 검증형 리졸버(Cloudflare 등)를 사용하는 사용자에게 간헐적으로 접속 실패가 발생할 수 있음

### 확인 요청 사항
1. ns1.uhost.co.kr(202.31.187.220) 서버의 EDNS0/대용량 UDP 패킷 처리 설정 점검 (방화벽, 로드밸런서, DNS 서버 소프트웨어 버전 등)
2. 위 증상이 topecai.co.kr에만 국한된 것인지, 해당 네임서버를 사용하는 다른 도메인에도 동일하게 나타나는지 확인
3. 조치 완료 후 회신 부탁드립니다.

### 재현 방법 참고
EDNS0(DNSSEC OK 비트 포함) 쿼리를 지원하는 도구(`dig +dnssec`, Python `dnspython`의 `want_dnssec=True` 등)로 ns1.uhost.co.kr에 반복 질의하면 재현됩니다. 일반 `nslookup`/`dig`(EDNS 옵션 없이)로는 재현되지 않으니, 반드시 EDNS0 옵션을 포함해서 테스트 부탁드립니다.
