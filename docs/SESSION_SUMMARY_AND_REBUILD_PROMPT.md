## 1부. 이번 세션에서 반영된 내용

### 1.1 계약서/사건 AI 분석 품질 개선
- **다중 첨부파일 통합분석**: 문서 업로드 시 여러 파일을 첨부해도 첫 번째(주 파일) 외 나머지는
  분석에서 빠지던 문제를 수정. `extract_all_document_files()`가 주 파일(최대 12,000자) + 첨부파일
  전체(합산 72,000자 풀에서 파일당 최소 2,000~최대 8,000자 배분)를 하나의 AI 프롬프트로 결합.
  (`apps/api/app/services/document_pipeline.py`, `litigation_pipeline.py`)
- **AI 분석 진행률 그래픽화**: 0~100% 원형 게이지(`ProgressGauge.tsx`)를 문서 상세 화면에 표시,
  단계별 가중치 기반 진행률 계산(`pipeline_progress.py`)을 15초 폴링으로 갱신.
- **Claude + Gemini 듀얼 AI 교차검토**: 주 분석(Claude)이 끝나면 보조 AI(Gemini)가 독립적으로
  2차 의견(동의수준/추가 리스크/누락 포인트)을 생성해 별도 카드로 표시. `SECONDARY_AI_PROVIDER`
  설정 시에만 동작, CONFIDENTIAL 문서는 자동 제외.
- **소송·분쟁 사건 AI 질의응답 로봇 아이콘**: 순수 SVG로 제작한 로봇+저울 아이콘
  (`LegalRobotIcon.tsx`)을 해당 탭/헤더/빈 상태에 적용.

### 1.2 마케팅 홈페이지 + 실서버 배포로 전환
처음에는 정적 홈페이지(Netlify)만 만들었으나, "내부망이 아니라 실제 인터넷에서 파일 업로드·AI
분석까지 되어야 한다"는 요구에 따라 **사내 시스템 전체를 실제 서버에 배포**하는 것으로 방향을 바꿨다.

- **DigitalOcean Droplet**(NYC1)에 Docker Compose로 전체 스택(postgres/redis/minio/libreoffice/
  api/worker/web/caddy) 배포.
- 도메인 `topecai.co.kr` → 서브도메인 `app.topecai.co.kr`을 서버 IP에 연결.
- **Caddy 리버스 프록시**로 `/api/*`는 FastAPI, 나머지는 Next.js로 라우팅.
- **HTTPS**: 처음엔 Caddy 자체 Let's Encrypt 자동발급을 시도했으나, 기존 네임서버(iNames 무료
  네임서버)가 DDoS 방지용으로 EDNS0 쿼리를 초당 임계치 초과 시 차단하는 정책 때문에 인증서 발급이
  계속 실패. **Cloudflare로 네임서버 이전**(`ali.ns.cloudflare.com`/`carlos.ns.cloudflare.com`)
  후 Cloudflare Universal SSL(Flexible 모드: 브라우저↔Cloudflare는 HTTPS, Cloudflare↔서버는 HTTP)로
  해결 — Caddy 설정은 `:80` 캐치올만 남기고 도메인별 자동 HTTPS 블록은 제거.

> ⚠️ **주의(재현 시 참고)**: Cloudflare 대시보드에서 `.kr` 같은 일부 ccTLD 도메인을 "Add a domain"
> UI로 추가하면, Cloudflare 내부의 "도메인 등록대행 이관 가능여부 확인" API가 미지원 TLD에 대해
> 에러를 던지면서 화면이 무한 로딩에 빠지는 버그가 있다(자동 스캔이든 수동 입력이든 동일). 이 경우
> Cloudflare REST API(`POST /zones`)를 직접 호출해 존을 생성하면 우회된다.

### 1.3 관리자 화면 확장 (신규 메뉴 2개)
- **리소스 모니터링** (`/admin/monitoring`): DB/파일 저장공간 사용량과 임계치(관리자가 GB로 직접
  수정 가능, `SystemSetting` 키-값 저장소 재사용), AI 토큰 사용량(오늘/이번 달/전체, provider별)을
  15초 자동 폴링으로 표시. `GET /api/admin/resource-usage` 신규.
- **로그 기록** (`/admin/logs`): 감사 로그(액션 종류/성공-실패 필터) + 로그인 시도 이력 두 탭.
  기존에 DB에는 쌓이고 있었지만 볼 화면이 없던 것을 신규 제작. **로그인 실패가 감사로그에 전혀
  기록되지 않던 버그**도 함께 수정(`AuditAction.LOGIN_FAILURE`가 정의만 되고 미사용이었음).

### 1.4 회원가입 시스템 (이메일 인증 + 관리자 승인)
로그인 화면에서 관리자가 계정을 직접 만들어주는 방식뿐이었던 것을, 직원이 스스로 가입 신청할 수
있도록 확장했다. 최종 흐름은 3단계:

```
가입 신청(ID/이름/휴대폰/회사이메일/비밀번호)
  → 이메일 인증 링크 클릭
  → 관리자 승인(역할 선택) ← 이 단계 전까지 로그인 자체가 차단됨
  → 로그인 가능
```

- **이메일 발송**: 처음엔 회사 SMTP(Mailplug, `smtp.mailplug.co.kr:465`)로 구현했으나, 운영 서버가
  올라간 **DigitalOcean이 신규 계정 스팸 방지 정책으로 outbound SMTP 포트(25/465/587)를 기본
  차단**하고 있어 실제 발송이 되지 않았다(TCP 연결 자체가 타임아웃, Gmail SMTP로도 동일하게 막혀
  있어 DigitalOcean 쪽 문제로 확인). DigitalOcean 지원팀 티켓으로 해제를 기다리는 대신, **Resend
  (HTTP API 기반 이메일 발송 서비스, 443 포트 사용)로 전환**해 즉시 해결. 코드는 `RESEND_API_KEY`가
  있으면 Resend를, 없으면 SMTP를, 둘 다 없으면 로그 출력만 하는 3단 폴백 구조.
  (`apps/api/app/services/email.py`)
- 발신 도메인은 실제 회사 메일 도메인(`topec.co.kr`)이 아니라 시스템이 관리하는 `topecai.co.kr`의
  하위로 인증(`no-reply@topecai.co.kr`) — DNS를 이미 Cloudflare로 옮겨놨기 때문에 Resend가 요구하는
  DKIM/SPF/MX 레코드를 바로 추가할 수 있었다.
- **관리자 승인 + 권한 부여**: 이메일 인증만으로는 로그인이 안 되고, 관리자 화면(관리자 → 가입 승인
  탭)에서 신청자를 확인 후 승인해야 최종 활성화된다. 승인 시 관리자가 체크박스로 추가 권한을 선택:
  - 일반직원 기본(대시보드/내 문서/계약서 업로드) — 항상 포함, 회원가입 시 자동 부여되는 `USER` 역할
  - 소송·분쟁 사건 접근 권한 — 신규 역할 `LITIGATION_ACCESS` (기존엔 전체공개였던 메뉴를 권한제로 전환)
  - 법무 검토함 접근 권한 — 기존 `LEGAL_REVIEWER` 역할 부여
  - 반려 기능도 포함(소프트 삭제 처리)
- **계정 상태 머신**: `User.approval_status` 컬럼 신규 추가 — `PENDING_EMAIL_VERIFICATION` →
  `PENDING_ADMIN_APPROVAL` → `APPROVED` (반려 시 `REJECTED`). 기존에 이미 활동 중이던 계정들은
  마이그레이션에서 전부 `APPROVED`로 유지해 소급 차단되지 않도록 처리했고, "소송·분쟁 사건" 메뉴가
  전체공개→권한제로 바뀌면서 기존 활성 사용자들이 접근권을 잃지 않도록 `LITIGATION_ACCESS` 역할을
  일괄 백필했다.
- **접근 제어 기본 원칙 확인**: "본인이 올린 문서/사건은 본인만 볼 수 있다(관리자 제외)"는 규칙은
  이미 백엔드에 구현되어 있었다(`document_access.py`, `legal_case/access.py` — 소유자 기준 필터 +
  관리자 전체열람 + 부서관리자(같은 부서)/법무담당자(배정된 건)의 기존 예외는 그대로 유지).

## 2부. 재현용 프롬프트

아래 프롬프트들은 **순서대로** 사용한다. 1번이 원래의 MVP 기획(기존 `PROJECT_PLAN.md` 기반)이고,
2~5번이 이번 세션에서 추가된 기능들이다. 각 프롬프트는 실제로 이 프로젝트에 사용했던 지시를 재구성한
것이며, Claude Code처럼 파일을 직접 읽고 쓰고 명령을 실행할 수 있는 에이전트에게 그대로 붙여넣을 수
있게 작성했다.

### 프롬프트 1 — 최초 MVP 구축

```
TOPEC이라는 회사의 사내 전용 법률검토 AI 시스템을 만들어줘. 외부 고객용이 아니라 임직원이
계약서나 소송·분쟁 문서(준비서면, 소장, 답변서 등)를 업로드하면 AI가 1차 검토를 지원하는
업무지원 도구야. AI는 최종 법률판단을 내리지 않고 법무담당자의 검토를 보조하는 역할이라는 점을
화면 문구에도 명시해줘.

기술 스택은 모노레포로: apps/api(FastAPI + SQLAlchemy + Alembic + Celery + Postgres/pgvector),
apps/web(Next.js 14 + TypeScript + Tailwind + TanStack Query), Redis, MinIO(S3 호환 파일저장),
LibreOffice 변환 서비스까지 전부 Docker Compose로 묶어줘.

필요한 기능:
1. 자체 로그인(사번 또는 이메일 + 비밀번호), 세션 쿠키 기반 인증, CSRF 토큰, 로그인 실패
   잠금정책, 2단계 인증(TOTP) 옵션
2. 역할기반 권한(RBAC): 일반사용자/부서관리자/법무담당자/경영진/시스템관리자
3. 계약서 업로드(PDF/스캔PDF/이미지/DOCX/HWPX/HWP/TXT), 텍스트 추출 + OCR
4. 계약유형 5종 이상 지원(하도급/설계감리CM/일반용역/NDA/MOU 등), TOPEC의 계약상 지위 선택
5. 조항 자동 분리·분류, 주요정보(계약금액/기간/당사자 등) 자동추출 + 사용자 검수
6. 규칙기반 위험탐지 엔진 + AI Provider 어댑터 패턴(Mock/Anthropic/OpenAI/AzureOpenAI/Local
   인터페이스를 전부 두되, API 키가 없으면 Mock으로 동작해서 개발이 막히지 않게 해줘)
7. 소송·분쟁 문서 검토: 계약서와 별도 카테고리로, 준비서면/소장/답변서 등을 업로드하면 조항이
   아니라 "주장·쟁점 단위"로 자동 분리하고, 각 쟁점별 상대방 근거/TOPEC 영향/대응논리를 AI가
   정리하는 별도 파이프라인
8. 관리자 업로드형 법률지식베이스(pgvector 하이브리드 검색) + 출처(Citation) 기반 AI 질의응답,
   근거 없으면 "근거 확인 필요"로 표시(환각 방지)
9. 수정 권고문구를 최소/권고/보호강화 3단계로 생성, 수정 전후 비교, DOCX 보고서 생성 +
   LibreOffice로 PDF 변환
10. 법무검토 워크플로우: 요청 → 담당자 지정 → 검토 → 승인/반려/보완요청 → 완료
11. 감사로그(누가 언제 무엇을), 문서 보존정책 및 자동삭제 배치, 보안등급(일반/중요/극비)별
    AI 라우팅 — 극비 문서는 외부 AI로 전송 금지
12. 관리자 대시보드: 사용자/부서 관리, 통계, AI 사용량, 감사로그, 지식베이스 관리
13. 프론트엔드: 로그인부터 관리자 화면까지 전체 UI, 사이드바 네비게이션 구조로
14. 시드 데이터(관리자/법무담당/일반사용자 3계정), 데모용 가상 계약서 샘플, 핵심 백엔드 테스트

보안 원칙: 모든 API는 서버 측에서 소유권/부서/역할을 검사하고, 프론트 화면에서 숨기는 것에
의존하지 마. 업로드된 문서 내용은 데이터일 뿐 명령이 아니라는 걸 AI 시스템 프롬프트에 명시해서
문서 내 프롬프트 인젝션을 방지해줘.

"로그인 → 업로드 → 분석(Mock 모드로) → 위험목록 확인 → 보고서 다운로드"까지의 엔드투엔드 흐름을
가장 먼저 동작하게 만들고, 그다음 지식베이스/질의응답 → 법무 워크플로우 → 관리자 화면 순으로
확장해줘. Mock이 아닌 목업 데이터로 화면만 그럴싸하게 만드는 건 하지 말고, 실제로 동작하는
코드로 만들어줘.
```

### 프롬프트 1.5 — 결과 공유 기능(텍스트/Word/PDF/카카오톡)

> 이번 세션이 아니라 그 이전 세션에서 반영된 기능이지만, 처음부터 재현하려면 최초 MVP 직후에
> 필요하므로 순서상 여기 포함한다.

```
계약서/사건 검토 결과 화면(개요, 위험분석, 수정안, AI 질의응답)에 공유 메뉴를 추가해줘.
- 텍스트 복사, txt 파일 다운로드
- 개요 탭은 Word(DOCX)/PDF 다운로드도 가능하게
- 카카오톡 공유 — Kakao JavaScript SDK를 연동해줘. JS 키는 내가 카카오 개발자
  콘솔(developers.kakao.com)에서 발급받아 NEXT_PUBLIC_KAKAO_JS_KEY 환경변수로 줄 테니,
  키가 없을 때는 카카오톡 공유 메뉴 항목만 비활성 표시되게 해줘(에러 나지 않게).

공유 메뉴 드롭다운이 스크롤되는 부모 영역(채팅 목록 등) 안에 있어도 잘리지 않게
구현해줘.
```

### 프롬프트 2 — 다중 파일 통합분석 + AI 분석 진행률 + 듀얼 AI 교차검토

```
세 가지를 반영해줘.

1. 문서 업로드 시 여러 파일을 첨부할 수 있는데, 지금 AI 분석이 첫 번째(주 파일)만 읽고
   나머지 첨부파일은 무시하고 있어. 첨부된 모든 파일을 AI가 읽어서 통합적으로 분석하게
   고쳐줘. 단, 주 파일이 너무 길면 나머지 첨부파일들이 프롬프트에서 밀려나지 않도록 각
   파일에 합리적인 글자수 배분을 해줘.

2. AI 분석이 진행되는 동안 0%~100% 진척도를 그래픽(게이지/프로그레스바)으로 보여줘.

3. AI법률 로봇이 Claude와 Gemini를 같이 활용해서 검토하고 답변하게 해줘 — 주 분석은
   Claude로 하고, Gemini가 별도로 2차 교차검토 의견(동의 수준, 추가로 발견한 리스크,
   놓친 부분)을 내도록 해줘. 두 AI 중 하나만 설정되어 있어도 문제없이 동작해야 하고,
   극비 등급 문서는 교차검토도 건너뛰어줘.
```

### 프롬프트 3 — 실서버 배포 (DigitalOcean + 도메인 + HTTPS)

```
지금까지는 내부망에서만 쓸 수 있었는데, 실제 인터넷에서 접속해서 파일 업로드부터 AI 분석
결과 확인까지 전부 되도록 실제 서버에 배포해줘. 가벼운 데모가 아니라 지금 만든 시스템
전체(로그인, 업로드, AI 분석, 관리자 화면 전부)를 그대로 공개해야 해.

- DigitalOcean에 Droplet을 만들고 Docker/Docker Compose를 설치한 뒤 프로젝트 전체를
  배포해줘.
- 가지고 있는 도메인을 서버 IP에 연결하고, Caddy로 리버스 프록시를 붙여서 80/443 포트로
  API와 웹을 서빙해줘.
- HTTPS까지 자동발급되게 해줘. 만약 네임서버 문제로 Let's Encrypt 발급이 막히면(예:
  기존 네임서버가 DNS 쿼리를 속도제한하는 경우), Cloudflare로 네임서버를 이전하고
  Cloudflare의 무료 SSL(Flexible 모드)을 활용하는 방식으로 우회해줘.
- 프로덕션 환경변수(.env)는 새로 랜덤 값으로 생성하고, 쿠키 보안 옵션도 프로덕션에 맞게
  켜줘.
```

### 프롬프트 4 — 관리자 모니터링/로그 + 이메일 인증 회원가입

```
1. 관리자 화면에서 DB 저장 공간(사용량, 전체 업로드 임계치 용량), API(토큰) 사용 현황
   등을 실시간으로 볼 수 있는 화면을 별도 메뉴 항목으로 반영해줘.
2. 관리자 화면에서 로그 기록(누가 언제 무엇을 했는지, 로그인 시도 이력 포함)을 볼 수
   있게 조치해줘.
3. 로그인 화면에서 별도 회원가입 절차를 반영해줘(사용자 ID, 이름, 휴대폰 번호, 회사
   이메일). 회원가입 시 회사 이메일로 가입승인 메일을 발송해서, 그 메일의 인증 링크를
   클릭해야 회원가입이 완료되는 방식으로 처리해줘. 회사 이메일 도메인이 아니면 가입이
   안 되게 막아줘.

메일 발송은 실제로 동작해야 해 — SMTP든 다른 방식이든, 실제로 이메일이 도착하는지
검증까지 해줘. 만약 배포된 서버(클라우드 사업자)가 SMTP 포트를 막고 있으면, HTTP API
기반 이메일 발송 서비스(Resend, SendGrid, AWS SES 등)로 전환해서 해결해줘.
```

### 프롬프트 5 — 회원가입 관리자 승인 + 권한 부여, 대시보드 개인별 토큰 사용량

```
"법률지식 관리" 메뉴는 필요 없으니까 사이드바에서 빼줘.

그리고 신규 회원가입하면 관리자가 승인해서 권한을 부여하는 기능을 추가해줘.
1. 일반직원(대시보드, 내 문서, 계약서 업로드)은 기본으로 포함하고, 소송·분쟁 사건 접근
   권한과 법무 검토함 접근 권한은 관리자가 승인할 때 선택적으로 켜줄 수 있게 해줘.
   (이메일 인증까지는 되어도 관리자가 승인하기 전까지는 로그인이 안 되게 막아줘.)
2. 전체적인 시스템 기본 룰은 본인이 올린 내용은 본인만 볼 수 있게 하는 거야(관리자
   제외). 기존에 이미 활동 중인 사용자들의 접근 권한을 이 변경 때문에 잃지 않도록
   마이그레이션도 신경써줘.

마지막으로, 각 사용자별로 본인이 사용한 AI 토큰양을 볼 수 있는 화면을 대시보드 하단에
표시해줘(본인 것만, 오늘/이번 달/전체 누적 기준으로).
```

## 4부. 알아두면 좋은 함정들 (Gotchas)

실제로 이번 세션에서 겪었던, 재현 시 시간을 아낄 수 있는 이슈들이다.

1. **Docker Compose `ports:` 병합 버그**: `docker-compose.yml` + `docker-compose.override.yml`을
   같이 쓰면 `ports:` 같은 리스트 필드가 "교체"가 아니라 "이어붙이기"가 되어 포트 바인딩이
   충돌한다. 오버라이드 파일을 쓰지 말고 base 파일을 직접 수정하는 게 안전하다.
2. **내부 전용 서비스는 `ports:`가 아니라 `expose:`**: postgres/minio처럼 컨테이너 네트워크
   안에서만 접근하면 되는 서비스는 호스트에 포트를 열 필요가 없다. `expose:`를 쓰면 포트 충돌
   여지 자체가 사라진다.
3. **Cloudflare에 `.kr` 도메인 추가 시 UI가 멈추는 버그**: "도메인 등록 이관 가능여부" 체크 API가
   미지원 TLD에서 에러를 던지는데 프론트가 이를 처리하지 못하고 무한 로딩된다. REST API로 직접
   `POST /zones` 호출하면 우회된다.
4. **DigitalOcean은 신규 계정의 outbound SMTP(25/465/587)를 기본 차단한다**: 메일 발송 기능을
   만들 계획이면 처음부터 SMTP 대신 HTTP API 기반 발송 서비스(Resend 등)를 고려하거나,
   DigitalOcean 지원팀에 미리 포트 차단 해제를 요청해두는 게 좋다.
5. **이메일 플러스 태그(`user+tag@domain`)는 모든 메일 서버가 지원하지 않는다**: Gmail은 되지만
   국내 일부 기업 메일 서비스(Mailplug 등)는 하드 바운스(553 no mailbox)로 거부한다. 같은 주소로
   여러 번 테스트해야 한다면 테스트 계정을 삭제하고 재사용하거나, 플러스 태그 대신 실제 여러
   주소를 마련해야 한다.
6. **Next.js 웹 컨테이너는 코드가 이미지에 빌드되어 들어간다**: api/worker처럼 볼륨 마운트가
   아니므로, 프론트엔드를 고칠 때마다 `docker compose build web && docker compose up -d
   --force-recreate --no-deps web`이 필요하다(재시작만으로는 반영 안 됨).
7. **`docker compose restart`는 `.env` 변경을 반영하지 않는다**: 환경변수를 바꿨으면
   `restart`가 아니라 `up -d --force-recreate`로 컨테이너를 다시 만들어야 한다.
